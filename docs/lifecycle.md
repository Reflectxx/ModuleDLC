# Жизненный цикл и ограничения

## Callback-и модуля

Все callbacks получают `ScriptContext` и выполняются клиентской логикой
ModuleDLC:

1. `onEnable` — когда пользователь включает модуль.
2. `onTick` — раз за клиентский тик, пока модуль включён.
3. `onFrame` — на каждом кадре, пока модуль включён.
4. `onWorldRender(ctx, render)` — во время рендера мира, пока модуль включён.
5. `onDisable` — когда пользователь выключает модуль, файл скрипта удаляется
   или модуль отключается после ошибки callback.

Используйте `onDisable` для отмены временных изменений, например для сброса
спринта или освобождения собственных ресурсов.

## Ошибки

Если callback выбрасывает исключение, ModuleDLC записывает его в лог и
отключает модуль; в меню такой модуль остаётся видимым с красной рамкой и
пометкой `(error)`. Ошибки загрузки и выполнения также сохраняются с полным
stack trace в `mdlc.log` в папке игры; при подключённом игроке в чат выводится
уведомление с именем файла. Ошибка регистрации/компиляции не заменяет последнюю
успешную версию скрипта. Проверяйте `ctx.inGame()` и не используйте
`ctx.player()`/`ctx.world()` до подключения к миру.

## Hot reload

Наблюдатель следит за корневой папкой `config/moduledlc/scripts`. Создание,
изменение или удаление поддерживаемого файла приводит к загрузке, замене или
выгрузке модулей именно этого файла. Вложенные папки не отслеживаются.

При успешной замене прежние модули источника выключаются, после чего
устанавливается новая версия. Для модулей с тем же `id` переносится состояние
включения; новая версия запускает `onEnable`. Текущие значения настроек не
переносятся.

## Что доступно сейчас

- Регистрация модулей, категорий и настроек.
- Включение, выключение, client-tick и per-frame callbacks.
- Доступ к локальному игроку, загруженным игрокам, цели прицела, block ID,
  здоровью, сытости и выбранному слоту.
- Отрисовка HUD-объектов текста, прямоугольников и изображений; перемещение
  разрешённых объектов мышью при открытом чате.
- Переключение спринта и слота хотбара, анимация руки, vanilla-взаимодействие
  с целью и использование предмета.
- Локальные сообщения и отправка обычного сообщения в чат.
- Команды клиента с префиксом `.`, строковое хранилище скрипта,
  поиск блоков в загруженных чанках и 3D-рисование во время рендера мира.
- Горячая загрузка и выгрузка `.js`, `.java` и `.kt`.

## Чего пока нет как отдельного Script API

- Подписки на произвольные события Minecraft помимо `onEnable`, `onDisable`,
  `onTick` и `onFrame`.
- Бинды клавиш или пользовательские экраны.
- Произвольный 2D-рендер вне HUD-объектов и пользовательские шейдеры.
- API для отправки произвольных пакетов.
- Автоматическая выгрузка скрипта во вложенных папках.

`ctx.minecraft()` и объекты, возвращаемые игровыми методами, являются
Java-объектами клиента. Их публичные методы доступны скрипту, но это не заменяет
удобные и стабильные обёртки для перечисленных выше функций. Версии Minecraft
могут менять детали Java API.

## Доверие скриптам

Скрипты исполняются с полномочиями процесса Minecraft, а не в изолированной
песочнице. Загружайте только код, которому доверяете.
